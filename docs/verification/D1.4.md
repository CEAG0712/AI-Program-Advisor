## G. Four failure paths

**F1 — HTTP 400.** Symptoms: fixed `Invalid recommendation request.` Evidence: fresh parser 13 and full recommendation suite 24; controller lines 38–43, policy 14–30, filter 14–29. Isolation: distinguish malformed/oversized transport errors before guard from parsed invalid object/media type at controller. Diagnosis: malformed JSON, wrong numeric type/bounds, missing skills, unknown authority key or unsupported content type. Safe handling: fixed sanitized 400, no-store; no raw parser text, payload or SQL details. Verification: aliases, malformed/oversized JSON, content-type variants and exact-key tests passed. Only recommendation route errors are sanitized; lookalike/unrelated paths retain existing behavior, including existing parser messages. Do not claim application-wide sanitization.

**F2 — HTTP 401.** Symptoms: valid parsed request with missing/wrong/malformed bearer gets `Valid demo bearer credential required.` Evidence: guard 9–18/24–27 and full SQL/HTTP auth tests. Isolation: check body parser outcome first, then header format, configured mapping, symbol attachment. Diagnosis: no matching configured credential. Safe handling: deny; do not default tenant or accept query/body academy. Verification: both tenant mappings, malformed headers, wrong tokens, and bidirectional spoof attempts passed. Malformed unauthenticated JSON can receive 400 before 401 because parser runs first; no authenticated read follows that parse failure.

**F3 — genuine no-match HTTP 200.** Symptoms: `{"recommendations":[]}`. Evidence: successful real SQL read then budget 0 or hours 1 in integration; policy 35–46. Isolation: establish query succeeded before interpreting an empty eligible set. Diagnosis: no stored active authorized offer satisfies all declared constraints. Safe handling: return valid empty collection; invent no offers, waive no labels, infer no skill. Verification: real no-match, exact and just-below constraints passed; D1.2 independently tested empty B catalog and unaffected A. No-match means no suitable offer under this policy, not no inventory worldwide.

**F4 — dependency/overflow HTTP 503.** Symptoms: fixed `Catalog temporarily unavailable.` Evidence: repository 25–34, unit test 90–106, real closed-port integration. Isolation: separate connection/refusal, pool wait, statement timeout and candidate overflow using trusted internal diagnostics; client body intentionally cannot distinguish. Diagnosis: failed read or 1001st returned active row. Safe handling: refuse; never convert into empty business success or rank first 1000 silently. Verification: real refused TCP connection, process health still 200; repository unit tests at 0, 1000, 1001 and rejection. Overflow is unit-tested, not a 1001-row real SQL experiment. LIMIT bounds returned row count, not total scan/sort cost, row payload size, throughput or production scalability.
